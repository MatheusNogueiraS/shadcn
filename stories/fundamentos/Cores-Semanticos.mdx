# Semânticos

Os semânticos dizem para que cada cor serve e apontam para uma fundação diferente em Light e em Dark. Os componentes usam **somente semânticos**.

Para mudar uma cor, edite os arquivos em `tokens/` e rode `pnpm tokens`: `src/styles/tokens.css` é gerado e não deve ser editado à mão.

Os semânticos ficam em pastas por papel, como no Figma: `neutral`, `brand`, `danger`, `success`, `warning`, `info`, `focus`, `data` e `shadow`. Dentro de cada papel, uma subpasta por uso: `bg` para fundo, `text` para texto e `stroke` para qualquer contorno. As pastas só organizam: o nome do token é a classe, como `bg-danger-subtle` em `danger/bg`. Um `stroke` vira a classe do lugar onde é aplicado: `stroke-default` é usado como `border-default`, `ring-default` ou `outline-default`.

## Opacidade nos componentes

A opacidade vem depois da barra, como em `bg-control/50`, e lê a escala de opacidade das fundações: `/50` é o `opacity-50`. Use só valores que existem na escala.

Os usos ficam agrupados por função, como os semânticos acima ficam por uso. A variante diz o estado: `hover:` é hover, `disabled:` é disabled, `data-open:` é selected. Sem variante, o token diz: `bg-control/50` é o fundo de campo, `bg-divider/50` é separador. Um uso que a tabela não reconhece cai em **sem função**. A tabela lê o código dos componentes e se atualiza sozinha.

## Regras de uso

- **Branco sobre laranja é uma decisão da marca.** O contraste de `orange-500` com branco fica abaixo do mínimo AA de 4,5:1. O painel de acessibilidade vai apontar isso no botão principal, e é uma exceção conhecida.
- **Nomes do shadcn continuam funcionando.** `bg-primary` e similares são apelidos em `src/styles/legacy-aliases.css`, para que `shadcn add` não traga componentes sem cor. Ao adicionar um componente, troque pelos semânticos.
